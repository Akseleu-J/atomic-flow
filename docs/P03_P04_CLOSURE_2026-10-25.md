## What changed

The existing semantic stage now derives resolved file dependency closure and
binds every file when unresolved relations prevent a narrow invalidation claim.
Artifacts retain separate bytes/body/API/docs/reference hashes, dependency
digests, extractor/prompt/model/config/language/project identity and cache keys.
Changed inputs invalidate the affected explanations and dependent narrative
fragments. Unchanged keys reuse the cache without a semantic call. Cache updates
remain transactional: budget refusal, malformed evidence, cancellation or source
drift do not publish a partly current result.

Assembly produces structural layers and entry points, source-evidenced narrative
tour and architecture fragments, inferred domain tags and resolved import/call
flows. These are inferred explanations, not independent semantic correctness.
Every fragment/flow carries current source/node/cache identity. Surviving symbols
and unresolved relations appear in the review. This does not claim runtime flow
coverage or correctness of an LLM's narrative.

`SemanticProvider` uses the existing `TaskBudgetBackend`, one durable task ledger
shared by every semantic call. It does not choose a provider or read credentials.
Invalid JSON retains charged usage; unknown outcomes retain the existing hold;
there is no local retry loop. The caller explicitly supplies backend/config and
cancel callback. The earlier `SemanticBudget` remains a separate callback-count
ceiling, not a replacement for physical cost accounting.

Read-only `graph_operation` serves inspect/search/explain/chat/impact/tour through
SDK, CLI and MCP. Chat is extractive current-source Q&A; cached semantic summaries
are optional and must pass project/source/dependency freshness validation. Missing
summaries remain `not_assessed`. No operation grants read-before-edit proof,
mutation permission or implicit model/executable invocation. Unsupported adapters
and output byte-cap omissions are explicit. Evidence is never trimmed inside a
source span while retaining a complete flag.

## P04 editing loop and exact evidence

Context packs now expose byte-cap omissions, partial coverage, a conservative
estimated token cap and `read_proof=False`. A suggested read plan is not an actual
source read. Existing continuation/read-coverage checks still require the complete
current source before an edit; symbol/range edits retain their hash, exact
old-text, scope and rollback checks.

Owned edit/rollback operations pass their exact changed paths to
`ToolContext.refresh(changed_paths=...)`, using the P02 incremental tree refresh.
The activation index reuses its incremental update interface. External watcher
events remain hints: an existing graph store is reconciled through P02 before
source refresh/acknowledgement; errors do not silently acknowledge freshness.

`verification_plan` maps changed paths through dependency closure to affected
files/tests. Unsupported/config/deleted/unresolved inputs yield `impact_status=
unknown`, broaden in-loop checks and retain a full final-regression requirement.
Binary/unsupported data is reported, never sent to a Python AST adapter. Static
links are recommendations; `runtime_coverage=not_assessed` is explicit. The parent
integrator connects this helper to the final completion gate and checks current
source hashes independently.

The previous `grounding_score(checked=0) == 1` false assurance is corrected:
zero checked identifiers yields `None` and versioned `verification_report.status=
not_assessed`, with denominator zero. Nonempty identifier checks are named
`identifier_presence`, never generic semantic grounding. Critic verdict remains
model opinion. The report includes shown-source coverage/partial omissions and
states that repository completeness/semantic correctness were not assessed.

Explicit citation `lines` now require valid exact coordinates inside the current
cited node, complete shown source, and a fresh content hash. Host checks the actual
bytes and records the redacted exact quote and source digest. Invalid, stale,
out-of-node or incomplete evidence drops the citation and downgrades an `ok`
model verdict. A citation without coordinates remains not_assessed for span
verification instead of receiving a fabricated span PASS.
