## What was done

1. **Baseline indicators** — new `tools/p00_baseline.py` (stdlib only) records a
   reproducible card: source HEAD/dirty state, config digest, Python/platform
   identity, cold `import atomic_flow` in a fresh interpreter (5 samples), a
   full `build_tree` of this repository with the production ignore profile
   (1 sample per run by cost), `load_tree`, tree artifact bytes/SHA-256 and
   final process RSS. Windows RSS uses `K32GetProcessMemoryInfo` with an
   explicit `psapi` fallback; non-Windows uses `resource`.
2. **Measured card** — `validation/p00-baseline-20261024/card.json`:
   cold import median **0.089 s**; self tree build median **5.52 s**
   (this checkout, default ignore profile); process RSS **36.05 MiB**.
   These are host-load-dependent indicators with recorded dispersion, not an
   SLO and not a performance claim. An earlier faulty variant that bypassed
   ignore profiles (indexing `.venv`/`.local-tools`, 111 s) was discarded and
   is not evidence.
3. **Acceptance registry** — `validation/p00-baseline-20261024/acceptance-registry.json`
   records existing evidence with explicit status kinds (LOCAL_PASS / CI_PASS /
   ORACLE_PASS …), the open gates (W6/W7/W8/W9, P01–P14, E00–E08) and the
   pre-registered comparison hypothesis with its budgets (no paid calls in P00;
   any live run follows `REAL_API_BENCHMARK_PROTOCOL.md`).
4. **Coverage map** — the W1–W9 regression coverage map is generated by a
   separate read-only audit and stored beside this document as
   `validation/p00-baseline-20261024/coverage-map.json`; gaps recorded there
   are inputs for P01+ regressions, not closures.
