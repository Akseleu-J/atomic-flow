# pytest6116 fixed pip-generated wrappers: independent template comparison

This is a candidate byte verifier and a review of an existing worker hash receipt, not an ordinary test admission. The five console entrypoints are derived from the pinned 25-wheel `optional+pexpect` profile using the existing wheel RECORD/SHA audit and `merge_plans` collision checks. The exact paths and entrypoint strings are fixed in `tools/p07_pytest6116_wrapper_verify.py`; an extra or different entrypoint fails closed.

The script template was independently read as bytes, without importing target code, from publisher `pip-23.0.1-py3-none-any.whl` SHA256 `236bcb61156d76c4b8a05821b988c7b8c35bf0da28a4b614e8d6ab5212c25c6f`: `pip/_vendor/distlib/scripts.py` SHA256 `0669132a68939389b6723fa2b9e9626adc33deeb7ff52b000415b9d6f9d09d95`. Its simple POSIX shebang and template yield exact expected bytes for the fixed `/usr/local/bin/python` and the three listed module/function entrypoints. This analysis is scoped to the pinned pip version, Linux and fixed interpreter path; it is not a general pip/distlib wrapper verifier.

For CI 40930969344, artifact 12923017273 SHA256 `c19b1aa71ef44d7e09edd1fc9cd212c590bbe9a3fcca318701539ba4f79b3ab0`, the five hashes in `diagnostic/generated-console-scripts.json` match those independently derived candidate bytes. The artifact contains only the worker's hashes, **not the raw wrapper bytes**; therefore this is reported-hash consistency and does not itself independently prove installed bytes. The previously observed pip version is not an independent byte audit of installed pip code.

`verify_wrapper_bytes` requires a caller to extract exactly five regular non-symlink wrapper files from a verified stopped container, compare the byte strings and preserve the result; it does not itself authenticate the container, actual pip installation, `sysconfig`, source tree, publisher signature or worker report. A later separate CI must check those controls, retain the raw bytes or independent hashes, and bind the checked image and runtime. Even then generated wrapper provenance is one environment gate, not TaskRunner/ordinary admission or a model-quality claim.
