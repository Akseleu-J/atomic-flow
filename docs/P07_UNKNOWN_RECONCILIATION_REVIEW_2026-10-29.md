# P07 paid UNKNOWN reconciliation — read-only review

This review describes the current code and a **proposed, unimplemented** evidence and recovery contract. It does not authorize a provider call, change any owner or budget, clear a hold, or approve a retry. Where the provider cannot supply authoritative attribution or actual cost, the original attempt must remain UNKNOWN; lack of a visible record, a timeout, or a queue state is not proof that it was unsent or free.

## Current behavior and its boundaries

* `tools/p07_model_broker.mjs:110-169` persists admission intent, obtains a reservation, persists the claim before one physical send, then records received result, settlement and completion. On an existing unresolved record it publishes UNKNOWN without a new send. Its returned `sent: false` describes **that invocation**, not proof that the original physical attempt never reached the provider.
* `tools/p07_paid_campaign_ledger.mjs:185-231` writes local state and requires an exact authoritative checkpoint acknowledgement at each transition. Unknown checkpoint writes or reads latch the running adapter; reopen is permitted only when the complete local state hash, sequence and fixed profile fingerprint agree with the remote checkpoint. `admit` at lines 286-307 blocks new sends while another original call or hold remains unresolved, across all owners. `accounting` and `settle` at lines 276-340 retain unsettled reserves, account provider usage exactly in nanoUSD, and add persistent holds when actual cost exceeds reserve or a budget ceiling. The exported surface at lines 342-351 is `journal`, `admit`, `settle`, and `snapshot`; there is no separately implemented operator API that turns an UNKNOWN original record into a resolved decision or clears a campaign hold.
* `tools/p07_github_checkpoint_store.mjs:16-24,61-99` stores a bounded canonical four-field checkpoint: schema, sequence, full-state SHA256 and profile fingerprint. Content-blob CAS plus an acknowledged commit checks consistency, not independent provider attestation. The remote checkpoint is hash-only: it cannot reconstruct missing local state, model responses, billing evidence, request context or the operator decision. A mismatch must not be fixed by simply overwriting one side.
* `tools/p07_kaggle_proxy_adapter.mjs:183-216` prevents duplicate IDs only in the adapter instance and sends a bounded, non-retried POST. Its request body and headers do **not** transmit `call_id` as an idempotency key, and its output sets `attempt_id` to the local `req.call_id`; this is not a provider-issued request ID or evidence that a provider deduplicated a request. Durable broker records provide the restart hold; the in-memory `sent` set alone does not survive restart. The actual provider's query, billing, correlation and idempotency capabilities remain unqualified.
* The separate `src/atomic_flow/reconcile.py:40-129` reconciles framework task/charge/effect records, requires actor, reason, evidence bytes and explicit nonnegative charge, and uses an evidence-derived reconciliation ID with idempotent crash recovery. It hashes evidence bytes; it does **not** establish source authenticity, provider attribution or paid campaign checkpoint consistency. `src/atomic_flow/budget.py:133-151` requires the original spend reservation and refuses conflicting repeat settlements. These framework functions do not themselves clear or reconcile the P07 host campaign ledger.
* `src/atomic_flow/backends/github_queue.py:312-328` is an observation of the original queue call and response, not paid ledger settlement. `src/atomic_flow/backends/routing.py:143-158` clears a quota attempt under a supplied evidence hash only, and explicitly does not settle money/effects or authorize replay. Queue observation, quota reconciliation, framework charge accounting and host campaign accounting are separate artifacts and must not be represented as one completed transaction.
* `tests/p07_unknown_restart_checkpoint_test.mjs` supplies synthetic in-memory GitHub/provider fault injection: lost acknowledgement after each transition, failure before remote result commit, and loss of UNKNOWN publication. It demonstrates restart blocking and no repeated fake send under those cases. It does not test a real provider, attest a billing result, or implement operator resolution. Its inclusion in `.github/workflows/integrations-release.yml` is pending the source revision and CI result that contains it.

## Proposed evidence required before a future manual resolution

These fields describe a gate to design and test, **not an existing schema or an executable procedure**:

1. **Immutable original identity and authority.** Record the campaign, original queue `call_id` and `request_sha256`, exact owner and owner authorization, task and arm, model/backend, framework and workflow SHAs, frozen profile hash/fingerprint, wire configuration, unique original reservation ID and its amount. Bind historic aggregate and owner spend, named owner caps, task/arm/total caps, call limit and deadline to the original frozen profile. An owner is not interchangeable with another owner even when they share a campaign.
2. **Checkpoint and local-state chain.** Preserve immutable copies of the original local ledger and queue/journal evidence without credentials; independently hash their exact bytes, record the authoritative remote branch/path, full Git commit and content blob, checkpoint sequence, state digest and fingerprint, and each observed pre/post state. Correlate the local canonical state with the exact acknowledged remote state. If a remote write acknowledgement was lost, determine the actual branch state read-only; a lost response is not proof that a write failed. If local bytes are missing or differ from the hash-only checkpoint, keep the gate closed and preserve all evidence; no rollback, recreation, branch reset or local hand-edit is an automatic recovery.
3. **Provider-side outcome and cost.** Obtain independently attributable provider evidence binding the specific physical request to the exact original owner/account, provider endpoint/model and authoritative attempt identifier, timing and final state. For a sent call, require final actual token usage and billed monetary amount/currency with the source and precision preserved, including settlement or evidence that billing remains pending. A genuine provider statement that the original attempt was never accepted may support a non-send decision only if its coverage, identifier and authority prove that particular attempt was absent; merely failing to find a record or observing an HTTP timeout is insufficient. No current code establishes such an authoritative correlation for a lost response.
4. **A precise decision with actor and immutable evidence.** Require a named authorized operator, reason, evidence bundle digest and evidence provenance, original request/reservation identity, the specific resolution category, provider actual charge where known, and explicit decision to preserve or clear each applicable hold. The same evidence and decision must be replay-idempotent; a changed cost, actor authority, original call identity or evidence must be rejected for separate review, not produce a second settlement. A zero charge needs positive proof. The evidence bundle must be retained securely without credentials, and summaries must not contain secrets.
5. **Atomic, recoverable accounting transition.** Design a durable intent, recheck the original checkpoint and exclusive lock, append exactly one bound campaign settlement/decision, fsync and obtain exact remote CAS acknowledgement of the next sequence, then update and independently reconcile the framework spend/task/session and quota records. Crash injection must cover every boundary, including unknown CAS acknowledgements and queue publication, while preserving the original reservation until the relevant durable transition is proven. Source evidence must bind any recovered result to the original physical request; lack of a model response is not evidence of model quality.
6. **Post-resolution admission is a separate decision.** Re-read the authoritative checkpoint and complete local ledger, recalculate historic plus actual and unresolved reserves at campaign, owner, task and arm levels, physical-call count, deadline, quota and explicit owner/provider authority. If actual exceeds reservation or any cap, preserve the appropriate campaign hold and account the full charge. Even a correctly reconciled original attempt grants no automatic retry, account switch, higher cap, fresh source version or study-profile admission.

## Open engineering and qualification gates

* Implement and independently review a typed, durable, operator-authorized P07 campaign resolution schema and API with original-call binding, conflict rejection, exact evidence provenance, idempotency, locks and atomic recovery. Define how framework charge records and the host campaign ledger are coordinated without losing holds during partial writes. Existing framework reconciliation is useful but is not this integration.
* Verify whether the actual provider exposes authoritative per-attempt correlation, billing completeness, receipts and any idempotency mechanism for the reviewed endpoint; do not assume these exist. Qualify the exact owner/account and actual response schema under the authorized protocol before any live action. If attribution or charge cannot be verified, leave UNKNOWN unresolved.
* Add meaningful fault-injection tests for changed evidence/amount/owner, duplicate resolution, every pre/post local write and remote CAS interruption, unavailable/stale provider evidence, response publication, cross-owner blocking, over-cap settlement, restart, framework/host divergence, and quota hold coordination. Verify real remote GitHub durability separately from fake transport, without generating a paid model request.
* Freeze the cohort, owner/model/profile, permitted envelopes and reservations; independently qualify tariffs, quota and permissions before physical execution. A successful scripted or fake-fetch test does not close those gates, establish provider quality or authorize paid execution.
