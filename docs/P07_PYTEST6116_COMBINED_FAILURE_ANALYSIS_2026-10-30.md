## Two forked crash/exit tests: established incompatible private API

`TestExecutionForked::test_exit_propagates` and `::test_suicide` fail at `xdist/boxed.py:49` because 1.18.2 calls `item._getfslineno()`, which this public pytest `Function`/`Node` does not provide. The latter test intentionally kills the forked process; the former raises `pytest.exit.Exception`, whose public pytest runner re-raises `Exit`. These paths differ from the two earlier xdist focused tests, which exercised only normal passing/failing function reports and thus did not demonstrate crash/exit compatibility.

Further incompatibility is visible statically: the same xdist 1.18.2 crash helper calls `runner.CallInfo(lambda: 0/0, "???")`, while this public pytest's `CallInfo` has five attrs fields and its supported `from_call` constructor. Changing only `_getfslineno` would likely expose the next incompatibility; this is an inference pending an isolated execution. `pytest-forked` 1.0.2 publisher wheel SHA256 `5fe33fbd07d7b1302c95310803a5e5726a4ff7f19d5a542b7ce57c76fed8135f` contains a `forked_run_report` implementation that checks for `_pytest.compat.getfslineno` and `CallInfo.from_call`; the public pytest base does contain the former. This static evidence suggests a candidate compatibility implementation, but does not prove equivalent crash reporting or exit propagation. Newer xdist does not ship the historical `xdist.boxed` module that these tests explicitly import.

## Three xdist progress tests: missing finish-event forwarding is a strong hypothesis

`TestProgressOutputStyle::test_xdist_normal`, `::test_xdist_normal_count`, and `TestProgressWithTeardown::test_xdist_normal` run nested pytest with `-n2` and assert full progress/count text. Their preserved bounded reasons show pattern mismatches; the complete nested transcript and return code were not retained. This prevents ruling out worker initialization, unexpected extra output, or unrelated plugin effects solely from the current artifact.

The static call chain is nevertheless specific. Public `src/_pytest/terminal.py:403-454` writes low-verbosity progress in `pytest_runtest_logfinish`, whereas xdist 1.18.2 `xdist/remote.py` forwards `pytest_runtest_logstart` and `pytest_runtest_logreport` but has no `pytest_runtest_logfinish` hook; its `xdist/dsession.py` has no corresponding finish-event relay. By contrast, the independently SHA256-checked publisher wheel `pytest-xdist` 1.28.0 (`b0bb4b0293ee8657b9eb3ff334a3b6aac4db74fd4a86b81e1982c879237a47eb`) contains finish-event handling in `xdist/remote.py:100-103` and forwarding to the local hook in `xdist/dsession.py:243-244`. This is a plausible precise version-compatibility explanation, **not yet a runtime proof**; 1.28.0 lacks `xdist.boxed`, and no complete 1.28 runtime closure or full suite has been qualified.
