# P07 matched driver: snapshot gaps and candidate bindings — 2026-10-29

Scope: independent static review of `tools/p07_matched_runner_probe.py`, its matched-arm declaration, `runtime_digest`, the queue backend and both runner paths. This is a design and evidence note, not a change to execution authority. The probe checks selected current fields twice, then returns hashes; it does not hold a lock across validation and execution, build the matched driver, or authorize a provider call. No paid inference was performed.

## Confirmed current coverage

`validate_arm_runtime` matches the frozen task/arm queue identity, selected wire settings, selected limits, arm budget, strategy and exact `CheckSpec`; `inspect_runner_snapshot` checks exact runner/backend/obligation types, public protected-path digest membership, the ordinary-test image/mode and deadline, then rechecks selected values and runtime/queue bindings. It returns the destination hash, but does not establish that destination is approved. `runtime_digest` (`src/atomic_flow/agents/envelope.py:59`) serializes `AtomicConfig`, the selected backend config and name, hashes two policy files, records the trust boolean, and binds the supplied obligation digest. It excludes API keys and normalizes selected backend max retries to zero; the queue's own `_verify_binding` independently checks its original config and serialized queue identity/binding.

These are useful drift checks, not a comparison of every input used during a run. Atomic and flat intentionally use different strategies: comparing whole runtime digests for equality would reject expected arm differences and still not prove equal inputs. A new common-field projection must explicitly declare which fields must match and which arm-specific differences are permitted.

## Concrete gaps

1. **Resource limits and callbacks are absent from the snapshot.** `TaskRunner.__init__` stores `resource_limits`, `approval_callback`, `question_callback`, `cancel_check`, `task_backend` and mutable execution state (`src/atomic_flow/agents/task_loop.py:75-103`). `_resume_locked` and source traversal use `resource_limits`; Atomic passes approval/question callbacks to `Orchestrator` (`task_loop.py:1043`), while flat passes them to `ToolContext` (`tools/p07_flat_task_runner.py:182-188`). `runtime_digest` has no runner argument and does not bind these fields. The probe only rejects a non-null capability factory; it does not establish callback or effective `ProjectLimits` equivalence.

   A local scripted-only reproduction using the retained real-object test fixture changed `runner.resource_limits` to `ProjectLimits(max_files=5)`, replaced `approval_callback`, and changed `backend.root` to a new empty journal directory. `inspect_runner_snapshot` returned successfully before and after with the **same runtime digest**. No queue send or model call occurred. This demonstrates that this snapshot does not bind those values; it does not prove that a separate host admission or durable broker ledger can be bypassed.

2. **Queue transport, journal root and timing are not checked by `_verify_binding`.** `GitHubQueueBackend` stores a transport object, journal root, cancellation callback, polling interval and wait interval separately from its backend config (`src/atomic_flow/backends/github_queue.py:144-174`). `_verify_binding` (`:182-186`) checks config, serialized identity/destination, and `transport.binding` (with a fallback to the declared identity), but not transport object identity/implementation, journal root, callbacks or effective poll/wait values. `_require_clear` uses `self.root` for unresolved local records (`:199`), and sending uses the current transport (`:292`). A new transport with the same apparent binding, or another journal root, is not distinguished by this check. Other authoritative checkpoint/ledger gates remain separate and were not bypass-tested here.

3. **Request, plan, actual writable scope and initial task state are not supplied to the probe.** The manifest projection retains the public packet and writable paths; `inspect_runner_snapshot` receives neither actual query/plan/allowed paths nor a task object. `TaskRunner.run_plan` accepts those inputs and creates/approves a task (`task_loop.py:277`); `FlatTaskRunner.run_flat` constructs its own generic plan (`tools/p07_flat_task_runner.py:89`). `require_approval` separately binds a task plan, resolved project and observed source manifest, but this probe cannot establish that the approved request, plan, initial budget events, source baseline, candidate selection and path scope correspond to the frozen pair. State can also change after the snapshot. Preserve plan/strategy differences while matching public issue bytes, scope, baseline, order and common budget.

4. **Role prompts, effective tool sets and policy consumption are not a common-arm attestation.** Runtime digest binds policy-file bytes and trust boolean, but not files read by `PromptRegistry` (`src/atomic_flow/llm/prompts.py:83-90`): a trusted project prompt takes precedence over a user prompt, then builtins. Atomic's `Orchestrator.answer` resolves them (`src/atomic_flow/llm/orchestrator.py:693`), whereas flat has its own `FLAT_TOOLS` and `SYSTEM` (`tools/p07_flat_baseline.py:26-37`). Tool/role differences can be deliberate experimental treatments; they must be frozen and reported, not blindly made equal. Verify effective source, text hashes, allowed tool sets, policy/trust decisions and runtime code identity; do not assume that matching a policy file hash proves a policy was used identically.

5. **Source and environment provenance are declarations, not proofs.** A directly constructed `CheckObligation` validates its own immutable shape, while environment digest is a supplied value (`src/atomic_flow/check_obligation.py:100-160`). The probe checks every explicitly listed public protected path against the packet, but does not independently audit every source Git object, unchanged/absent checker config, whole obligation inventory, installed runtime files, Docker image ancestry or the evidence represented by `runtime_admission_sha256`. Nor does it prove the currently resolved workspace is the admitted source. Its `obligation_digest` is an identity for the supplied object, not proof of host qualification.

6. **Snapshot checks cannot guard all execution or reconcile effects.** `_require_replan_runtime` can compare a runtime digest on internal-replan continuation (`task_loop.py:695-710`), and the normal task machinery has approval, scope, source and accounting checks. The new probe does not establish that every actual planning/send/tool/check/publication effect is bound to the frozen pair, that the deadline and physical-call budget are enforced at every effect boundary, or that remote checkpoint ACK/UNKNOWN reconciliation has completed. Double reads reduce simple drift but cannot prevent mutation between checks or after return. A model response, completed runner, or this probe is not a hidden-oracle grade.

## Candidate contract and verification sequence

1. Define a versioned canonical **common envelope** bound into the frozen cohort: exact issue packet hash and bytes provenance, source/base and admitted runtime evidence identities, actual writable/protected scope, common hard limits and deadlines, effective `ProjectLimits`, approved queue destination and journal/checkpoint identity, callback policy and resolved policy/trust data. Keep physical secrets out of the envelope. Include separate arm-specific, explicitly reviewed strategy, role prompt hashes, tools and framework implementation hashes; do not require those treatment variables to be identical.
2. Resolve effective values using host-owned factories. For absence, bind explicit sentinels rather than silently omitting values. Arbitrary callables cannot safely be frozen by hashing `repr`, `id`, or a function name: either refuse injected callbacks for the study or admit a fixed implementation/configuration by stable reviewed code hash and immutable parameters. Treat transport implementation, destination and journal location as separate identities and preserve durable remote checkpoint as the authoritative accounting gate.
3. On independent baseline workspaces, verify public Git blobs, source selection, protected and absent configuration paths, wheel/image provenance and exact `CheckSpec`. Compare actual query and writable scope to the packet and prevent cross-arm artifact, context or solution leakage. Generate an immutable per-arm start receipt with common-envelope digest, treatment identity, deadline and resolved role/tool/policy digests.
4. Bind the receipt to the actual task/queue request and check it at admission and at relevant effect boundaries, including before each physical send and final publication. A host-owned lease/guard and post-effect source/evidence checks are required; no finite preflight hash alone eliminates concurrent external modification. Preserve reserve → remote checkpoint ACK → one send → settlement and refuse unresolved or ambiguous outcomes.
5. Exercise synthetic adversarial cases: mutate `ProjectLimits`, callback policy, transport with the same displayed binding, journal root, polling/wait values, role prompt file, query, allowed path, protected/absent source files, and deadline between preflight and effect. Each unauthorized change must be refused before its respective effect; inject remote checkpoint failure and UNKNOWN across restart and both owners, verify no second physical send, and separately test compatible unchanged runs. Verify actual envelope equality and intentional arm differences from the resulting receipts, not merely from caller-supplied declarations.

Until those tests and corresponding isolated TaskRunner/queue integrations are reviewed, this contract is a proposal; P07 matched pairs, independent grading, holdout and final review remain open.
