# Этап 4: калибровка задач и первый live QA-пилот

22 октября 2026. **Этап 4 остаётся открытым.** Реализованы две разные проверки:
калибровка сценариев исторических изменений и парный read-only QA-пилот с живой моделью.
Успешное редактирование кода живым агентом на 30–50 задачах нескольких репозиториев ещё не измерено.

## Исторические изменения

`benchmarks/pilot/tasks.json` фиксирует шесть изменений своего репозитория, каждое
с RU/EN формулировкой: полное постраничное чтение файла, приоритет запрета,
повреждённая policy, версия Task JSON, однозначный patch, явный ответ пользователя.
Это **6 независимых изменений и 12 формулировок**, известные разработчикам,
не held-out benchmark. Базовый коммит — `7b15406a9541330b374fe1d8a5ec48ac07efbdc1`;
исправленный — `0bae3ade4124e3772f20160aa3c8b0c565c497a3`.

`evaluation.py` экспортирует tracked-файлы через Git archive в отдельный временный
каталог; история Git, dirty checkout и grader туда не копируются. Links/special files,
выход за каталог и архивы больше 128 MiB отклоняются. Отдельный интерпретатор
импортирует именно проверяемый snapshot. Ошибки инфраструктуры/зависимостей,
неизвестный результат и timeout не считаются успешной калибровкой.

Локальный запуск на известных доверенных коммитах:

```powershell
python tools/evaluate_tasks.py --execution local --output validation/pilot-calibration-local.json
```

Результат: **6/6 base FAIL и 6/6 gold PASS**, ноль вызовов модели.
`local` явно разрешает выполнение собственного исторического кода на хосте и не
подтверждает sandbox. Docker — default без fallback:

```sh
python tools/evaluate_tasks.py --output colab-results/task-calibration.json
```

Docker CI получает полную историю checkout и выполняет эту команду после сборки
`atomic-flow-checks:local`; JSON включён в validation artifact.
Grader хранится вне workspace и передаётся процессу как доверенный Python-код.
Это регрессионные проверки поведения, а не защищённый от злонамеренного кандидата grading service.
Проверки patch/ask_user покрывают заявленные в grader happy/error paths; остальные
безопасностные свойства из формулировок задачи требуют штатного regression suite.
Запуск модели для исправления этих исторических задач пока не реализован.

## Парный live QA-пилот

Backend: бесплатная квота Kaggle №2, `google/gemini-3.1-flash-lite-preview`.
Выбранная сначала Qwen ответила HTTP 404; отдельный отчёт сохраняет этот отказ
и неизвестную usage, а не маскирует его нулевой стоимостью. Счётчики квоты до/после
этого отказа не изменились. Gemini проверена минимальным запросом, затем запущена
на восьми вопросах из существующего fixture-корпуса. Пользователь явно разрешил
передачу публичных fixtures в Kaggle. Секреты расшифрованы только в памяти;
платные ключи OpenAI/Anthropic не использовались, credential-файлы не создавались.

Каждый вопрос имеет два прогона с одной моделью: однократный ответ с полным исходным
корпусом/каталогом node IDs и текущий atomic-flow medium с retrieval/ролями/tools.
Порядок стратегий чередуется. Критерии общие: существующие regex/citations/abstention
и corpus-level identifier checks. Конфигурация: 1 попытка Orchestrator, 2048 output tokens,
5000 context budget для atomic; baseline получает весь корпус. До запуска установлены
ограничения 64 chat-вызова всего, 8 на trial, порог $0.50 reported quota cost;
backend retries=0. HTTP parameter negotiation может добавить транспортные запросы.
Порог проверяется до следующего вызова и может быть превышен одним ответом;
это не гарантия биллинга провайдера. Неизвестная стоимость останавливает дальнейшие вызовы.

| Метрика | Полный контекст | atomic medium |
|---|---:|---:|
| Автоматически прошли | 6/8 | 7/8 |
| Chat-вызовы | 8 | 26 |
| Входные токены | 188883 | 112107 |
| Выходные токены | 1242 | 3070 |
| Reported quota cost, USD equivalent | 0.04908375 | 0.030797325 |
| Quota cost / автоматический успех | 0.008180625 | 0.004399618 |
| Суммарное wall time, s | 15.577 | 35.954 |

Общий reported cost **0.079881075**, фактическое изменение дневного счётчика
Kaggle **0.079881075** с погрешностью float. Это списание бесплатной квоты, не платёж.
Меньшее потребление входа/квоты сопровождается большим числом вызовов и временем.
Один небольшой прогон не устанавливает статистическую значимость или преимущество
graph retrieval: контексты, prompts и количество обращений различаются.

Два вида отказов требуют разбора до расширения эксперимента:

1. Оба ответа о выплатах правильно говорят об отсутствии данных, но автоматический
   `abstained` оказался false. Критерий также зависит от confidence; в первом сыром
   отчёте confidence/missing_context не сохранены, поэтому точную причину нельзя
   восстановить из него. Новые запуски сохраняют оба поля. Старые оценки не пересчитаны.
   У atomic также остались внутренние aliases `n19`/`n21` в тексте: проверка
   unknown_identifiers их отклонила, хотя нормализованные citations указывают на реальные узлы.
2. Ответ baseline о бесплатной доставке содержит правильный порог 50 и проходит
   текстовые шаблоны, но не проходит требование к ссылке на нужный узел.

Все **16 trials** и итоговая сводка сохранены. Последующая избыточная запись того же
итога упала с WinError 5 в OneDrive; повторных обращений к модели не было. Writer
теперь делает ограниченные повторы PermissionError, лишний финальный checkpoint удалён.
Для будущих запусков предпочтителен output вне синхронизируемой папки с последующим
копированием готового JSON. Во время пилота на диске обновилась только новая
оценочная обвязка; импортированный процесс продолжал работать с прежней версией.
Её текст восстановлен из точной истории patches и сохранён отдельно; это указано
в provenance, SHA-256 отчёта и core runtime тоже сохранены. Runtime core не менялся.

Воспроизведение при уже установленных **process-local** MODEL_PROXY_URL/API_KEY:

```sh
python tools/evaluate_qa.py --yes --output /tmp/atomic-qa.json
```

Команда не получает ключи из vault и не сохраняет их. Она использует только выбранные
Kaggle-модели; для повторения именно этого пилота default — проверенная Gemini.
Код fixtures читается как текст, не импортируется и не исполняется. Изменения исходников
не разрешены. Общая оценка сохраняет расходы и failed calls ещё до parsing ответа;
исключения провайдера записываются только по типу, без содержимого headers/URL.
