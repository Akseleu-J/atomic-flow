## Real standard-port service, separate DNS certificate

The function API reads HTTPBIN_URL=http://httpbin.org/ with no explicit port.
A real admitted HTTPBin0.4.1 application must listen on127.0.0.1:80 and TLS443
inside the same isolated worker. This preserves mixed-case scheme tests that
switch http/https while keeping the netloc and literal HTTPS endpoints in the
original suites. Two different ephemeral fixture ports cannot satisfy this API.

Only the task's exact mappings above are allowed. www.google.co.uk serves a
real HTTPBin response after an off-host redirect in2148/2317, preserving the
actual Location and Authorization-stripping behavior. This feasibility is source
review only; actual redirect/alias health still needs measurement. No wildcard,
external DNS access or Internet route is proposed. Port1 remains closed and
negative DNS names remain unresolved.

Use network=none, no host mounts, all capabilities dropped, no added capabilities
and no-new-privileges. The reviewed sysctl
net.ipv4.ip_unprivileged_port_start=0 permits standard ports without granting
network administration capabilities to the target. Requests2317 additionally
needs the qualified exact10.255.255.1:80 timeout route and silent DROP in the same
owned target worker namespace. It cannot borrow another container's probe result.

The fresh disclosed public test leaf has CNhttpbin.org and exactly one DNS SAN,
httpbin.org, with no IP SAN. The CA and leaf use RSA2048/SHA256, appropriate CA
basic constraints, signing/server key usage and serverAuth. CA validity is at
most31 days; leaf validity at most15 days; current-time validation is mandatory.
The signing key is never installed. Record all actual material hashes, public
metadata, chain/key matching and current validity during a future build.
material_hashes is null in this prospective profile because no certificates have
been generated by it. A wrong CA must fail, and chain plus hostname verification
must remain enabled.

This DNS-SAN profile is distinct from3362's CN127.0.0.1/no-SAN overlay and must
not replace or relabel it. www.google.co.uk is used over HTTP in these inspected
redirect tests; no additional HTTPS SAN is admitted for that alias.
